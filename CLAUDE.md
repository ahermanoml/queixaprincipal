# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`qprincipal.com.br` — a Brazilian-Portuguese clinical decision-support tool, **Queixa Principal**, in five tabs, in this order: **Meu rascunho** (one big text: the clinician's own draft, saved per person on their **personal link** `qprincipal.com.br/<nome>`), **Prescrições** (pick a chief complaint / condition, assemble a prescription from prebuilt medication blocks, copy plain text formatted like the source plantão/UBS PDF prescriptions), **Escores** (ER scores), **Calculadoras** (infusion dilutions and bolus doses) and **Procedimentos** (technique, checklist and a note for the prontuário). Product rule: every piece of content can be copied as plain text ready to paste into the hospital system. Used mostly on the hospital desktop during shifts, but must work on a phone too.

A **static site with no build step**: plain HTML + CSS + classic `<script src>` files. No framework, no npm dependencies, no ES modules — so `index.html` works opened via `file://` as well as on GitHub Pages. The only network call is the personal-link API (`js/conta.js` → Cloudflare Worker, see *Contas*), and only on a personal link. `CNAME` pins the GitHub Pages custom domain. The dev-only browser checks live in `tests/` (Python + Playwright + Chrome).

## Development & deploy

- **Run/preview:** open `index.html` directly in a browser, or `python3 -m http.server` and visit it. Nothing to build.
- **Test:** `python3 tests/run.py` (see *Tests*). Run it before every push.
- **Deploy:** GitHub Pages serves `main`. Pushing to `main` publishes to `qprincipal.com.br` — a live medical site. Do not rename `CNAME` or `index.html`.
- Everything is client-side except the **personal links** (*Contas* below): a Cloudflare Worker + KV keeps each person's Meu rascunho, encrypted in the browser. No analytics, no third-party assets; the tools themselves make no network call. The repo is public: never commit identifiable patient data.

### Cache busting (`?v=`)

GitHub Pages caches assets, so a browser could combine a new `index.html` with an old JS/CSS file. Every local asset URL in `index.html` carries the same version token, e.g. `js/core.js?v=20261110r`. **Whenever any file under `css/`, `data/` or `js/` changes in a push, bump the token in every URL of `index.html`** (one search-and-replace; format `YYYYMMDD` + a letter for several releases on one day). New asset → add it with the current token.

## Data model (the part that matters)

`DATA` and `KW` are authored as **pretty-printed JSON** (double-quoted keys and string values, one element per line) — match that style; don't revert to compact unquoted JS object literals.

Each entry in `DATA` is a condition:

```js
{
  "id": "itu",                 // unique key; MUST also appear in KW
  "ic": "💊",                  // emoji shown in the list
  "nm": "ITU / Cistite",       // display name
  "sub": "sulfametoxazol · fosfomicina · ...",  // subtitle (also searched)
  "blocks": [ ...Block ]
}
```

A **Block** is one prescription variant / section:

```js
{
  "label": "Padrão — Ibuprofeno",
  "items": [ Item, ... ],
  "orient": ["texto de orientação", ...],  // optional patient-guidance bullets
  "menu": true,                             // optional; see below
  "mode": "internacao",                     // optional; "amb" (default) | "internacao" | "ped" | "ped_internacao"
  "sec": "offlabel",                        // optional; "padrao" (default) | "offlabel" (shown as "Outras opções")
  "peso": {"de": 3, "menor": 35},           // optional; block only applies to this weight range (see *Calculadora de peso*)
  "draft": true                             // optional; AI-drafted → shows a "rascunho" tag, needs clinical sign-off (unrelated to the "Meu rascunho" tab)
}
```

- `"menu": true` marks a "choose one of these" block — the UI shows an `escolha` tag instead of the **Adicionar receita** (add-whole-block) button, so items must be added individually. By convention these blocks also carry an `— escolha 1` suffix in their `label`.
- `orient` strings are not shown inside the block: `renderMid` gathers the `orient` of every block in the active mode (deduped) into the **Recomendações e instruções** section, where each line can be added on its own (or all at once). **Adicionar receita** on a block adds **only its medications** — orientations are always added separately, from that section (every condition, every mode). Added lines appear under an `ORIENTAÇÕES:` heading in the output.
- `"sec"` picks the **section** of the middle column the block belongs to (see *Prescription modes & sections*): `"padrao"` (default when absent) or `"offlabel"`. In the ambulatorial mode, **Padrão** is the guideline-based standard prescription (AI-drafted from current guidelines, so it carries `"draft": true` until signed off) and the `"offlabel"` blocks — displayed as **Outras opções** — hold every older ambulatorial block that the new padrão did not already cover ("alternatives", not the regulatory off-label sense). The UI label was renamed from "Off label" to "Outras opções", but the data key stays `"sec": "offlabel"` — **don't rename the key**. `orient` text that points the clinician to those blocks says "(VER OUTRAS OPÇÕES)"; the remaining "OFF LABEL" mentions in `DATA` are the regulatory sense (bula / via não aprovada) and stay as written. Internação and pediátrica were rebuilt the same way: each mode has its own guideline-based padrão blocks plus `"offlabel"` alternatives, all `"draft": true`; pediatric weight-based doses use the PESO spec.
- `"mode"` puts the block in one of **four combinations** of patient × setting, picked in the middle column by the **Adulto | Pediátrico** tabs and the **Ambulatorial | Internação** sub-option (see *Prescription modes & sections*):

  | `"mode"` | Shown in |
  |----------|----------|
  | `"amb"` (default when the key is absent) | Adulto › Ambulatorial |
  | `"internacao"` | Adulto › Internação |
  | `"ped"` | Pediátrico › Ambulatorial |
  | `"ped_internacao"` | Pediátrico › Internação |

  The `MODE_OF[pac][set]` table in the script maps the UI choice to these values. **Ambulatorial vs Internação follows one rule for adults and children:** *Internação* = care given in the hospital — PS/observação/enfermaria/UTI: EV or continuous drugs, crisis treatment in the PS, observação (e.g. anafilaxia, crise de asma no PS, dengue grupos C/D, plano C, pielonefrite EV, pneumonia internada, grande queimado, TCE em observação); *Ambulatorial* = what the patient takes home, including single IM doses given at the unit before going home (penicilina benzatina, ceftriaxona IM na otite, profilaxias, antitetânica). The pediatric blocks were split with this rule in 2026-11 (97 `"ped"`, 36 `"ped_internacao"`); keep new blocks consistent with it.
- **How the Padrão is organised (2026-11, owner's request "tudo de opções").** In Adulto › Ambulatorial (35 conditions) and Pediátrico › Ambulatorial (9), the Padrão shows the first-line options grouped by purpose — analgésico/antitérmico, AINE, dor intensa, antibiótico, antiemético, anti-histamínico… — at most ~4 groups / ~10 options; a group whose options exclude each other is a `"menu"` (`— escolha 1`), a group meant to be given together (e.g. dipirona + paracetamol intercalados, lavagem nasal) is a normal block. An item appears only once inside the Padrão. The old fixed combinations left the Padrão whole and unchanged, as `"sec": "offlabel"` blocks labelled **`Combinação pronta — …`** (one click away in Outras opções); their `orient` moved to the first new group. Second-line drugs and the owner's old blocks stay in Outras opções. Keep this shape when adding conditions.
- `"draft": true` flags AI-generated content awaiting the clinician's review — it renders a small `rascunho` marker (amber dot + word, the block itself is not tinted) in the block header (and on its lines in **Recomendações e instruções**, unless a non-draft block carries the same line). Drop the flag once a block is signed off. This `rascunho` tag has **nothing to do** with the **Meu rascunho** header tab (the clinician's own `MINHA` templates) — keep the two separate.

An **Item** is a positional array (tuple), **not** an object — in the file each element sits on its own line:

```js
[ "IBUPROFENO 300 MG", "01 CAIXA", "TOMAR 02 COMPRIMIDOS DE 6/6H POR 05 DIAS", route? ]
//   [0] med + dose       [1] quantity      [2] posologia (instructions)            [3] route?
```

- The 4th element (route) is optional and defaults to `ORAL`. Route constants are defined once at the top of the script: `ORAL, TOP, INAL, NASAL, AUD, SL, EV, IM, SC` (e.g. `"USO ORAL"`, `"USO TÓPICO"`, `"USO ENDOVENOSO"`, `"USO INTRAMUSCULAR"`). In the JSON `DATA` the route is written as the **literal string** (e.g. `"USO ENDOVENOSO"`), not the JS constant — the constants are only used in the script logic (`buildText`, `keyOf`, defaults).
- Drug names and doses are written in **UPPERCASE** by convention — match it.
- **Weight-based doses** use a 5th element, the PESO spec — then the route `[3]` is mandatory and the posologia contains the literal `{DOSE}` and/or `{FAIXA}` exactly once each. See *Calculadora de peso*.

```js
[ "DIPIRONA 500 MG/ML SOLUÇÃO ORAL (GOTAS)", "01 FRASCO", "DAR {DOSE} VIA ORAL DE 6/6H SE DOR OU FEBRE (25 MG/KG/DOSE)", "USO ORAL",
  {"kg": 25, "conc": 500, "gotas": 20, "un": "GOTAS", "max": 1000} ]
```

## Conventions that are easy to break

- **Adding a condition requires two edits** (both in `data/prescricoes.js`). Add the object to `DATA` *and* add a matching key to `KW` (same `id`). Search — the column filter and the busca única — only works through `KW[id]` (plus `nm` + `sub`); a condition with no `KW` entry is unfindable by keyword. The `id` also becomes the address `#/prescricoes/<id>`, so keep ids lowercase `[a-z0-9_-]` and never rename one that people may have bookmarked. The `KW` value should be a flat lowercase string mixing the display name, lay synonyms, symptom words, and every drug name in the block.
- **Output format mirrors the source PDFs — don't casually change it.** `buildText()` groups selected items by route (`groupByRoute()`), prints the route header, then numbered lines `NN- MED ______ qty` followed by the posologia, then an `ORIENTAÇÕES:` section with `# `-prefixed lines. `pad()` pads each med name with underscores out to the `RX_COL_WIDTH` (46) column, with a `RX_MIN_DASHES` (3) floor. Changing those constants, the `NN- ` numbering, route grouping, or the `# ` prefix changes what clinicians paste into their systems.
- **Dedup key is `(med + "|" + qty + "|" + route).toUpperCase()`** (`keyOf`, route defaults to `ORAL`). The same drug at a *different quantity or route* is treated as a distinct item and will not be deduped — keep that in mind when authoring near-duplicate items.
- **"Edição livre" (free-edit) toggle** stops `syncRx()` from overwriting the `<textarea>`, so manual edits survive. Logic that writes to `#rx` must respect the `freeEdit` flag.

## App logic flow

`renderConds(filter)` (`js/views/prescricoes.js`) builds the left list (filter matches `norm(nm + sub + KW[id])`; only conditions — there is no pinned entry any more) → clicking a condition (or `openCond(id)` from an address / the search) resets `currentPac = "adulto"` and `currentSet = "amb"` and calls `renderMid(c)` → clicking an item / **Adicionar receita** calls `addItem`, and clicking a line in **Recomendações e instruções** calls `addOrient`; they mutate the global `selected[]` / `orientSet[]` (`js/receita.js`) and call `syncRx()` → `syncRx()` re-renders the right-hand chips and regenerates the textarea via `buildText()`. Copy uses `navigator.clipboard` with an `execCommand("copy")` fallback.

## Header tabs, view registry, routing and search

The header tabs, the addresses and the global search all come from **one registry**. Each `js/views/<tab>.js` calls `registerView({...})` once (fields also documented above `registerView` in `js/core.js`):

| Field | Meaning |
|-------|---------|
| `key` | id of the tab: used in the address (`#/key`), in `body[data-view]` and as the tab's `id="tab-<key>"` |
| `desc` | one line shown on the tab's tile in the home screen (`#/inicio`) |
| `label`, `icon` | tab text; `icon` = an emoji kept as a fallback inside the tab (invisible): the tab shows the line icon mapped to its `key` in `css/icones.css` (`.i[data-v="<key>"]`, generic document icon for unmapped keys) |
| `cols` | ids of the `.grid` columns the tab shows (`#col-rx`, the receita, is shown too unless `rx: false`) |
| `rx` | optional: `false` = the tab hides the receita column. `showView` sets `#col-rx` `hidden` and `body[data-rx="off"]` (grid `248px 1fr` / `1fr`); the receita keeps its content, weight and open condition, and comes back on the other tabs |
| `layout` | `"lista"` (narrow column + wide column + receita: `248px 1fr 380px`) or `"texto"` (wide column + receita: `1fr 380px`); matching rules at the 1100px / 820px breakpoints, via `body[data-layout]` |
| `itemId()` | optional: id of the item open now; makes the item part of the address `#/key/<id>` |
| `open(id, how)` | optional: open item `id`, return `false` if it doesn't exist. `how` = `"load"` (address on page load), `"route"` (back/forward or a typed address), `"search"` (busca única) |
| `close()` | optional: back to "nothing open" |
| `search()` | optional: entries for the busca única, `[{id, title, sub?, kw?, text?, ic?}]`, read once on the first search. `kw` is searched but never shown; `text` is searched and the matching line is shown as a snippet |

Registered today, in this order: `rascunho` (**⭐ Meu rascunho** — the first tab; `cols: col-rascunho`, `layout: texto`, no `itemId` so the address stays `#/rascunho`, `open("<start>-<end>")` = scroll to a passage and select it, `search` = the passages between blank lines of the current text), `prescricoes` (**💊 Prescrições** — formerly the "Padrão" tab; `cols: col-cond, col-mid`, `layout: lista`, `itemId/open/close` = the open condition, `search` = the 64 conditions with `nm` + `sub` + `KW`), `escores` (**📊 Escores**; `cols: col-esc-lista, col-esc`, `layout: lista`, `rx: false`, `itemId/open/close` = the open score, `search` = the 26 scores — see *Escores*), `calculadoras` (**🧮 Calculadoras**; `cols: col-calc-lista, col-calc`, `layout: lista`, `itemId/open/close` = the open calculator, `search` = every calculator and every drug row — see *Calculadoras*) and `procedimentos` (**🩺 Procedimentos**; `cols: col-proc-lista, col-proc`, `layout: lista`, `rx: false`, `itemId/open/close` = the open procedure, `search` = name + subtitle + `kw` — see *Procedimentos*). Only the header tab was renamed: the **Padrão** section inside a condition (`SECS`) keeps its name.

### Adding a tab (later phases)

1. `data/<tab>.js` — the content, as pretty-printed JSON like `DATA`.
2. `js/views/<tab>.js` — the column markup it needs (add a `<section class="col" id="col-<tab>" hidden>` to `index.html`), its render/copy logic, and one `registerView({...})` at the end. Every piece of content needs a **copy** button that produces plain text.
3. Two `<script>` tags in `index.html` (data before the views, the view before `router.js`; the position among the views is the tab position), with the current `?v=` token — then bump the token.
4. If the tab doesn't need the receita, register it with `rx: false`.

Nothing else: the tab, `#/<tab>/<item>` and the global search follow from the registry. Don't add placeholder / "em breve" tabs.

### Tabs (`js/app.js`)

`renderTabs()` writes one `.top-tab` button (`role="tab"`, `aria-controls` = its `cols`) per view into `#top-tabs`, in registry order, and marks each view column `role="tabpanel"`. `showView(key)` sets `currentView`, `body[data-view]` / `body[data-layout]`, puts `hidden` on the columns of the other views, marks the active tab and scrolls the page to the top. The receita column is shared, and **switching tabs keeps each tab's state** (open condition, mode, weight, receita — nothing is re-rendered).

- The tab bar never wraps: it scrolls horizontally (scrollbar hidden), fades the edge on the side with hidden tabs (`.more-l` / `.more-r`), turns the vertical mouse wheel into horizontal scroll, and keeps the active tab scrolled into view. It was checked with 7 tabs at 1440 / 1366 / 1280 / 1024 / 390 / 320 px (`tests/shots.py` adds dummy tabs at runtime up to 7) and with the real 5 tabs at 1366 / 1024 / 390 / 320 px (`tests/integracao.py`). At ≤600px the tabs grow to share the width (`flex:1 0 auto`) while they fit; at ≤360px the tab font drops to 14px. With five tabs the bar scrolls on phones (390/320px): the tabs past the edge are half-visible under the fade (the hint that there is more) and the active tab is always scrolled into view (checked by `features.py`).
- **Layout:** `body` is a flex column — the header has free height and `.grid` is `flex:1; min-height:0`, so the columns fill the rest of the screen. At ≤820px the page scrolls as a whole (`html, body {height:auto}`, `body {display:block}`) so the sticky header stays pinned. The global `[hidden]{display:none !important}` utility rule sits at the top of the CSS.
- **Header:** light (`--panel`) and low: brand (℞ mark + title + subtitle) on the left, the busca única as a wide pill in the middle (max 620px), the theme button on the right; below, the tabs as text + line icon, the active one in the primary colour with a 3px indicator. ## Calculadora de peso

- PESO spec fields (5th element of an Item): `kg` (amount per kg **per dose**, in the drug unit) **or** `kgdia` + `vezes` (per kg per day ÷ doses/day) **or** `fixo` (fixed amount); `max` (cap per dose, in the drug unit — always set it with `kg`/`kgdia`); `conc` (drug unit per mL of the presentation; omit when the output is the drug unit itself, e.g. EV dose in MG or fluids in ML); `un` (`"ML" | "GOTAS" | "MG" | "MCG" | "UI"`, printed in place of `{DOSE}`); `gotas` (drops per mL, required for `"GOTAS"`).
- `doseTxt(spec)` computes from the global `peso` (`js/peso.js`): amount = min(kg × peso, max) (or `fixo`); ML = amount ÷ conc (2 decimals under 1 mL, else 1); GOTAS = round(amount ÷ conc × gotas); without `conc` the amount itself. Capped doses get "(DOSE MÁXIMA)". With no weight (or no dose for that weight) it prints `__ ML` / `__ GOTAS`.

### Weight bands — show only the band that applies

Many posologias used to list a table of weight bands ("ATÉ 10 KG …; DE 10 A 20 KG …; ACIMA DE 20 KG …"). With a weight typed, the site now shows **only the band for that weight**, with the arithmetic done; with no weight it shows the table exactly as before. Three mechanisms, all using the same range object `{de: ≥, acima: >, ate: ≤, menor: <}` (any subset; `fits(r)` is true when every given bound holds, and always true with no weight):

1. **Band table inside one posologia** — the table part of the posologia is replaced by the literal `{FAIXA}`, and the spec gets:
   - `"sem_peso"`: the **exact original text** of that part (no weight → the posologia reads exactly as before; keep this invariant),
   - `"faixas"`: `[{<range>, "txt": "...", "dose"?: {...}}, ...]` — first band whose range fits wins; `txt` replaces `{FAIXA}`; inside `txt`, `{=expr}` is arithmetic with `P` = weight in kg (only numbers, `P`, `+ - * / ( )`, `min`, `max`; results ≥ 10 are rounded to integers, smaller ones get 1 decimal), e.g. `"{=P*100} ML (100 ML/KG)"`, `"{=min(1500+20*(P-20),2000)} ML"`. A band's `dose` overrides the dose fields for `{DOSE}` (e.g. zidovudina 12 mg/kg for 4–9 kg, 9 mg/kg for 9–30 kg, `fixo` 300 mg from 30 kg). A weight outside every band falls back to `sem_peso` (and `__` for the dose) — never guess a band. Bands must not overlap.
   - Used in 23 items (2026-11): pediatric SRO/dengue, maintenance EV fluids (diarreia plano C, queimaduras — Holliday-Segar), zidovudina, dolutegravir, nebulized salbutamol, benzatina, loratadina (5 conditions), ondansetrona, ivermectina (escabiose, parasitoses), terbinafina (2); adult SG 4:1, ivermectina, cefazolina (3) and ceftriaxona dose by weight.
2. **One option per band in an "escolha 1" menu** — the item's spec has `"peso": {<range>}` (no dose fields needed; the route `[3]` is then mandatory). Out-of-range options are hidden when a weight is typed (oseltamivir 15/23/40 kg, benzatina 27 kg). Age-defined options (e.g. oseltamivir for < 1 year) have no `peso` and always show.
3. **Whole block for one band** — the block gets `"peso": {<range>}` right after `"label"` (the range is also written in the label): PEP-HIV < 35 / ≥ 35 kg, IST profilaxia < 45 kg, triptano ≥ 40 kg, codeína ≥ 40 kg, ivermectina ≥ 15 kg. Hidden when the typed weight is outside.

Rendering: `posHTML()` turns `{DOSE}` into `<b class="dose">` and `{FAIXA}` into `<span class="faixa">` (highlighted `.on` when a band applies); `fillDose()` resolves both for the receita text, at build time, so changing the weight updates items already in the receita. `applyPeso()` (called by `renderMid` and on every weight keystroke via `refreshDoses()`, no re-render so focus stays) updates doses and bands, toggles `hidden` on `.item[data-pf]` / `.block[data-pb]`, and fills each section's `.faixa-nota` ("Mostrando só o que vale para N kg — X opções de outra faixa de peso ocultas"). **Adicionar receita** skips out-of-range options; a receita chip whose option no longer fits the weight gets a red "⚠ fora da faixa do peso digitado".

- The weight box (`.peso-box`, `#peso`) shows on the **Pediátrico** tab (both sub-options, labelled "Peso da criança"), and on Adulto whenever a shown block has `peso` or an item has a spec ("Peso do paciente"). The weight persists across conditions/tabs and is cleared by **Limpar**. When any selected item has a spec and a weight is set, the receita starts with `PESO: N KG`.
- Single **eligibility** thresholds inside a posologia ("NÃO USAR COM MENOS DE 5 KG", "ACIMA DE 10 ANOS OU MAIS DE 30 KG") are not bands and stay as text; so does the diurese target line in the queimaduras orientations.

## Calculadoras (`#/calculadoras`)

Port of the owner's **dilui** shift calculator (infusion pumps, RSI doses, pediatric and adult emergency bolus doses), redesigned around what the doctor is looking for. It started as a byte-for-byte copy of dilui; since the clinical review of 2026-11 it is **corrected content**: dilui is the origin, not the truth, and the tests protect the corrected version (see *Divergências em relação ao dilui*).

- **Content** (`data/calculadoras.js`) was generated by a script from dilui's `index.html` (the region from the `DILUI — banco de drogas` comment to the `];` closing `EMG`), wrapped in `const CALC_DADOS = (() => { … return {INF, IOT, PED, EMG, RODAPE}; })();` so the dilui names don't become globals. Change doses only for an approved clinical correction, then add it to *Divergências* and refreeze the golden file (below); list suspected problems in `data/calc-revisao.js` instead of "fixing" them on your own. All of it is AI-drafted: every calculator header shows the `rascunho` tag (same meaning as `"draft": true`), and dilui's disclaimer/references (`RODAPE`) close every page.
- **Math.** The top of `js/calc-motor.js` is dilui's code (`num`, `fIn`, `fmt`, `fAuto`, `fML`, `fRate`, `concOf`, `rateOf`, `doseOf`, `perUnit`, `concLabel`, `dilOptions`, `bolus`, `byAge`, `rangeStr`, `CALC`, `viaPed`, `lma`, `pesoEst`, `pasMin`, `idadeTxt`, `isPed`, `rxText`, `kitText`), inside `CM = (() => {…})()` because dilui's `num`/`esc`/`$` differ from the site's; `num`, `CALC.salbutamol` and `kitText` were corrected in the review, the rest is unchanged. The bottom part turns dilui's HTML-building code into data with the same strings: `CM.linha(it, kg, age, ped)` → `{tipo: "fixo"|"bolus"|"calc"|"semPeso", main, small, sub, caps, nota, copy}`; `CM.infusao("dose"|"rate", rate)` → concentration, mL/h, the support line (dose/min, drops, duration), the alert (`msg`, `red`, `nivel`), `rx` (dilui's prescription text) and the titration table. State lives in `CM.S` (dilui's `S`). Other tabs (Procedimentos) read `CALC_DADOS.IOT` and `CM`'s dose helpers at runtime: keep their names and shapes stable.
- **Typed numbers** (`CM.numInfo(s)` → `{v, milhar}`; `CM.num(s)` = `.v`): with a comma, dots are thousands and the comma is the decimal ("1.250,5" = 1250.5, "0,5"); without a comma, a number shaped like `1.000`, `25.000`, `12.345.678` (regex `^[1-9]\d{0,2}(\.\d{3})+$`) has thousands dots ("25.000" UI of heparin = 25000; dilui read 25); any other dot is a decimal point ("1.5", "70.5", "0.500" = 0.5); garbage → NaN. Every input of the tab goes through `cxEnt(el, unit)` (weight, age, height, dose, rate, ampoules, diluent, ampoule-of-your-hospital amount and volume), which shows "entendido: 25.000 UI" next to the field whenever a dot was read as thousands. The weight still only accepts 0 < kg ≤ 250, so "1.000" kg is refused.
- **Pages** (`CX_PAGS`): the 18 infusions (`#/calculadoras/<dilui id>`, e.g. `nora`), `iot`, one page per `EMG` section (`emg-<slug>`) and per `PED` section (`ped-<slug>`); slugs in `CX_SLUG`. A row inside a page is `<page>.<index>` (`emg-arritmias.1`, `iot.ind0`): the busca única lists every drug row, and opening one highlights the row (`.hl`, ~2.4 s); the address then shows the page.
- **Weight = the global `peso`** (`js/peso.js`), starts empty. Typing it here updates `peso`, the Prescrições field and the receita (`refreshDoses()`); a `document` `input` listener picks up changes typed in Prescrições, and a second listener on `#btn-clear` resets weight, age and height/sex (no edits to core/peso/receita). With no weight nothing is computed from an assumed weight: infusion rate is disabled, step ③ shows a prompt, weight-based rows show the per-kg dose and "falta o peso" with no copy button. One-click chips (50–100 kg) and, for children, "Usar N kg" from the age (APLS formula shown) are explicit and label the weight "peso estimado" until a weight is typed.
- **Infusion page**: ① Preparo (preset chips, the recipe sentence, concentration; "Mudar ampolas…" opens amps/diluent/diluent type/ampoule-of-your-hospital fields), ② Dose ⇄ vazão (either input drives the other; −/+ step through dilui's `passos`; scale with `faixa` and `max`, marker amber outside the usual range and red above max; dilui's alert texts), ③ Texto pronto (**Copiar** and **＋ Receita** = `sendToRx`). The page is dense on purpose: with a weight, ② (both inputs, with the unit beside each number, and the range bar) and ③ (text + buttons) fit without scrolling at 1366×768, 1280×720, 1024×768 and 1440×900 — nothing is pinned over the inputs (checked by `layout()` in `tests/calc_features.py`). Keep it that way when adding content above step ③ (that is why the review box sits right after ③ on these pages). Enter in the dose or rate field copies. Then the titration table (rows clickable) and dilui's notes.
- **Situation pages / intubation**: rows in dilui's order, dose in large type, per-row Copiar / ＋ Receita (icons on narrow columns, with aria-labels). "Copiar tudo" only where the page is a sequence (`CX_TUDO`); intubation has "Copiar kit SRI" = `CM.kitText(ind, bnm)`: always **one** induction agent and **one** paralytic (never all four), starting from the owner's standard **etomidato + succinilcolina** (`CM.KIT_PADRAO`, indices into `IOT.ind` / `IOT.bnm`); the alternatives (cetamina, propofol, midazolam / rocurônio) are one-click chips above the button (`cxKit`; clicking the chosen one keeps it; **Limpar** returns to the standard). Children: "Atropina (se indicada)". The patient's weight is still never assumed. Cross-links between calculators: `CX_LINK_PAG`, `CX_LINK_LINHA`, `CX_POS_IOT`.
- **Review box "🔎 Para o revisor"** (`cxRevisorHTML`): a collapsed `<details class="cx-revisor">` on every page that has items in `data/calc-revisao.js` (`CALC_REVISAO`, keyed by page id; `_bomba` applies to every infusion page), kept apart from the dose tables. Two lists: **Mudou em relação ao dilui** (what this review changed, old → new) and **Para decidir** (open clinical decisions for the owner). Below the title on situation pages / intubation; right after step ③ on infusion pages. When the owner decides an item, remove it from there (and, if a dose changes, follow the refreeze steps). All of Calculadoras stays `rascunho`.
- **Tests**: `tests/calc_paridade.py` compares the site with `tests/calc_gabarito.json.gz` — the outputs of the **corrected site** for ~10 400 cases (every infusion × preset × weight × dose/rate, custom ampoule/diluent cases, every bolus row × weight × age, RSI kit, pediatric helpers, tidal volume), frozen from the site itself. Rows are compared as the site renders them (`cxLinhaHTML`). It then diffs that file against `tests/calc_gabarito_dilui.json.gz` (the same cases as the original dilui showed them, kept as history) and fails on any difference not attributed to an approved divergence (`DIVERG_LINHAS` / `item_do_caso` in the script; the counts per item are printed). `tests/calc_features.py` covers the behaviour (no-weight state on all 35 pages, ②/③ visible and unobstructed on the four hospital monitor sizes, weight sync, chips, age estimate, addresses, search, Copiar / ＋ Receita, keyboard, alerts, phone widths; `revisao()`: number parsing in every field, each corrected row, the RSI kit choice and the review box on each page) and, with `--shots`, the screenshots.
- **Refreezing after an approved content change**: (1) edit `data/calculadoras.js` (or the motor); (2) add a line to *Divergências* below and, if the change alters cases of the golden file, a `DIVERG_LINHAS` entry (table, section, row name or `calc:<key>`, item number) so the diff can attribute it; (3) `python3 tests/calc_paridade.py --congelar` — rewrites `tests/calc_gabarito.json.gz` from the current site and prints the per-item diff against dilui (it fails if something changed that no item explains); (4) read that diff, then run `python3 tests/run.py`. `python3 tests/calc_paridade.py --dilui path/to/dilui/index.html` rebuilds the dilui history file from an original copy (only needed if the case list changes; treat that file as untrusted input: run it only in headless Chrome).

## Procedimentos (`#/procedimentos`)

Step-by-step emergency procedures with a paste-ready procedure note. **All content is AI-drafted and unreviewed**: every procedure has `"draft": true` (shows the `rascunho` tag), `"revisado": null` (the page says "Ainda não revisado") and its own `"fontes"`. Text is original (not copied from Whitebook/WeMEDS/books). No drug doses here: `"calc"` links to the Calculadoras page instead.

### Data model (`data/procedimentos.js`)

```js
{
  "id": "dreno",                       // address #/procedimentos/dreno — lowercase [a-z0-9_-], never rename
  "area": "torax",                     // a PROC_AREAS key (via-aerea, torax, vascular, abdome, neuro, cardiaco)
  "nm": "Drenagem de tórax", "sub": "dreno · selo d'água · …",
  "kw": "dreno de torax drenagem …",   // searched (list filter + busca única), never shown: synonyms + abbreviations
  "draft": true, "revisado": null,     // revisado: "AAAA-MM-DD" after the doctor signs it off (then drop draft)
  "pendencias": ["…"],                 // points the doctor must decide/confirm for THIS procedure (guideline variations,
                                       // values not confirmed at the source); shown as a collapsed "Para o revisor" box
                                       // only while draft is true — empty it (or drop draft) once he has decided
  "fontes": ["…"],                     // references used for this procedure
  "calc": [["emg-analgesia", "Analgesia e sedação"]],   // optional links to Calculadoras pages (ids of CX_PAGS)
  "indicacoes": ["…"], "contra": {"absolutas": ["…"], "relativas": ["…"]},
  "material": ["…"],                   // the checklist (+ "Copiar material")
  "preparo": ["…"],
  "tecnica": ["passo", {"t": "passo", "cuidado": "…"}, {"t": "passo", "dica": "…"}],   // one action per step
  "depois": ["…"], "complicacoes": ["…"],
  "registro": {
    "aprovado": "2026-11-10",          // the owner approved this standard (date); shown in the Fontes box with "resumo"
    "resumo": "Padrão do registro: …", // one line describing the standard (what is pre-filled, what stays blank)
    "variacoes": [{"campo": "guia", "rotulo": "Ultrassom", "curtos": {"GUIADA POR ULTRASSOM": "Guiada por US", …}}],
                                       // 1–2 main technique variants shown as one-click chips at the top of the note
    "padrao": {"calibre": "28", …}, "campos": [...], "modelo": ["linha com {var}", "…"]}
```

- Keep every list short (one idea per line); callouts (`cuidado` / `dica`) only where they prevent a real error.
- **Registro (the note).** `modelo` is one string per output line, written in UPPERCASE like the doctor's own laudos (`data/rascunho.js`). `{id}` = required variable: its value (uppercased) or `____` while empty, so a blank is obvious; `{id?}` = optional: if empty, the **whole line** is dropped. Each variable has exactly one field in `campos`, and each field is used in the template (checked by the tests). A field is either an object `{"id", "rotulo", "tipo": "opcoes"|"texto"|"num"|"derivado", "opcoes"?: [UPPERCASE values], "fonte"?: "IOT.ind" (options read from `CALC_DADOS`), "un"?, "dica"? (placeholder), "opcional"?: true, "padrao"?}` or the id of a shared field in `PROC_CAMPOS` (`lado`, `consentimento`, `antissepsia`, `anestesia`, `tentativas`, `intercorrencias`, `obs`). Keep fixed template text to what is inherent to the procedure — anything that may or may not have happened is a field. `prLinhas(p, vals)` returns the note as lines of pieces (fixed text, or `{c, t}` for a field's value) and `prTexto(p, vals)` joins them: pure/deterministic.
- **The standard (padrão) — approved by the owner on 10/11/2026 for all 10 procedures** (including the 22 cm tube depth). Every field that has a default is pre-filled, so one click copies a correct note for the typical case: usual technique, material, sizes, drugs and doses, uneventful course (1 attempt, no complications). A default is `"padrao"` on the field (shared ones in `PROC_CAMPOS`: clorexidina alcoólica, lidocaína 2% 10 mL, 1 tentativa, sem intercorrências) or in the procedure's `"registro.padrao"` map, which wins (`null` removes a shared default). **Two exceptions never get a default: the side (`lado`) and findings/measured results** (volume, aspect, opening pressure, Cormack, rhythm after the shock, indication, time…): leave them without `padrao` and they show as `____` (clickable) with their controls in the quick row under the text. Optional fields (`obs`, and **`consentimento`**, an optional `{consentimento?}.` line of its own) never have a default: consent is a legal attestation that is often false in an emergency, so the standard carries no consent sentence; "＋ Consentimento" adds it and counts as "ajustado" (the owner decides per procedure — see each `"Consentimento: …"` line in `pendencias`). When you change a standard, update `registro.resumo` (and `aprovado` once the owner signs it off). **Toracocentese** defaults to landmarks without ultrasound (sitting, posterior: linha escapular média or axilar posterior, 1–2 EIC below the upper limit of dullness, 5–10 cm lateral to the spine, never below the 9th rib); marcação prévia / guiada por US are one click away. The other procedures with an ultrasound field keep their default.
- **IOT drugs** are a `"derivado"` field (`"de": "sri"`): computed from `peso` (default 70 kg), `indutor` and `bloqueador` (their default pair is **`CM.KIT_PADRAO`**, the same standard as the Calculadoras RSI kit — one place for both tabs; never name them in `registro.padrao`) with the Calculadoras intubation table (`CALC_DADOS.IOT`, `CM.bolus`) — never type mg/kg or concentrations here. Inductor at the bottom of the table's range, blocker at the top (RSI dose); the volume is rounded to what is drawn up (whole mL from 5 mL, 0.1 mL below; x.5 rounds down) and the mg come from that volume: 70 kg → `ETOMIDATO 20 MG (10 ML) + SUCCINILCOLINA 100 MG (10 ML) — PESO 70 KG` (Calculadoras shows the computed dose, 21 mg / 70–105 mg; same pair, different rounding). In `PR_DERIVADOS` each derived field lists the fields it uses (`usa`, not in the template) and returns its text in pieces (`partes`), so the inductor, blocker and weight are each clickable inside the drug line.
- **Figures** (`PROC_FIGURAS`, at the top of `data/procedimentos.js`): `{"<proc id>": [{"arquivo": "dreno-3.svg", "passo": "tecnica.7", "titulo", "legenda"}]}` — the file lives in `img/procedimentos/`, `passo` = `<preparo|tecnica|depois>.<n>` (1-based) and the figure is drawn right under that step (an unknown step puts it at the end of the steps). To add figures: copy the files and add the lines; a procedure without figures renders normally. The tests check that every listed file exists and every step exists.
- **Adding a procedure:** append an object to `PROCS` with all the blocks above, `registro.padrao`, `registro.resumo` and 1–2 `registro.variacoes` (the tests reject a missing block, an unknown area, a variable without a field, a field without a variable, a default outside the options, a duplicate id or a stray `{}`); put abbreviations in `kw` (and in `nm`, e.g. "(CVC)", if the abbreviation should rank first in the search); run `python3 tests/run.py`.

### Page — two tabs: Registro and Como fazer

- Left: the list grouped by area, filterable. Middle, one calm column (reading width): **title + `rascunho`** and the segmented **Registro | Como fazer** (`.pr-guias`, `role="tablist"`; ← → switch). A fresh load opens on Registro.
- **Registro** (`#pr-g-registro`): one card with the state chip (`padrão` / `ajustado · N mudanças` / `editado`), the **variation chips** (`.pr-var`, `registro.variacoes`; one click, the choice stays), **↺ Voltar ao padrão** (only when something differs), **Editar texto** and the big **Copiar**; then the note (`#pr-texto`, uppercase monospace, never scrolls inside). **Every field value in the text is a clickable piece** (`.pr-tk`, `role="button"`, `tabindex="0"`, dotted underline; blanks highlighted): an option field opens a small menu (`#pr-pop`, current option ticked; ↑ ↓, Enter, Esc returns to the piece; "Deixar em branco" for blanks, "Tirar esta linha" for optional lines); a free-text/number field turns into a small input in place (Enter confirms, Esc gives up, blur confirms). Voltar ao padrão restores every adjustable field and keeps the quick-row values. There is no "Ajustar" box any more.
- **Como fazer** (`#pr-g-como`): **Material** (a collapsed box: checklist, Copiar material, Desmarcar), **Passo a passo** as the main reading (preparo + técnica + depois, one numbering, cuidado/dica callouts, figures under their step), then collapsed boxes: **Indicações e contraindicações**, **Complicações**, **Doses** (links to Calculadoras, only where `calc` exists), **Para o revisor** (drafts only) and **Fontes** (with the approved standard).
- Requirement: at 1366×768, 1280×720, 1024×768 and 1440×900 the tabs, the whole note, Copiar, the variation chips and the quick row are on the first screen for every procedure. Keep templates and quick rows short enough for that (the layout test fails otherwise).
- Keyboard: Tab reaches every piece of the text; Enter/Space opens it; Enter in a quick-row text field moves to the next control; Ctrl/Cmd+Enter copies from anywhere on the page.
- **Phones:** Registro comes first; when the card's Copiar is off screen (or under the sticky header) on the Registro tab, a fixed bottom bar (`#pr-barra`, Copiar registro) appears (IntersectionObserver); menu options are ≥ 40 px tall; `body.pr-com-barra` adds bottom padding, and a `focusin` handler keeps a focused control out from under the bar and the header.
- Look: follows *Theme, colours and icons* — only tokens (no literal colour in `css/procedimentos.css`; text on the primary uses `--on-accent`, blanks `--mark`/`--mark-ink`, the note `--mono`), the Registro card on `--sunken` without border, list rows like `.cond`, labels without spaced capitals, line icons (`<span class="i i-copy">` in Copiar, `i-plus` in the "＋" buttons, the check and chevron drawn with `--i-check` / `--i-chevron` masks), no emoji as icons. Text/background pairs of this tab are ≥ 4.5:1 in both themes (calculated). The figures keep their own light background in the dark theme.
- State per procedure (values, edited text, open tab, ticked material, open boxes) lives in memory for the session (`prEstado`) and survives tab switches and the Calculadoras round trip; a fresh load starts from the standard on the Registro tab with every box closed. Nothing is stored.
- Tests: `tests/proc_features.py` — structure (blocks, ids, fields ↔ variables, defaults inside the options, the standard's only blanks are the never-default fields, approved `resumo`, 1–2 valid `variacoes`, figures with existing files and steps, determinism, optional lines), behaviour (on load: Registro tab, no Ajustar box, standard shown, Copiar copies exactly it, every adjustable field has a piece in the text; every field changed by clicking its piece, "ajustado", Voltar ao padrão; toracocentese without US by default and US one click away; IOT 70 kg values and recalculation by weight inside the text; blanks and quick row; ＋ Consentimento / ＋ Observação; Editar texto; state across tabs and the Calculadoras round trip; figures under their step; keyboard; addresses, filter, busca, material) and layout at the four desktop sizes for all 10 procedures (and the menu on screen) and at 390/320 px; `--shots` adds the screenshots of both tabs and of an open menu.

## Meu rascunho (`MINHA`)

`MINHA` is a pretty-printed JSON array of cards: `{"titulo", "grupo", "conds": [DATA ids], "linhas": [one string per line], "nota"?}`.

- The text is the clinician's own, kept **as they wrote it** (their spacing, dashes, abbreviations and typos) — don't reformat it into `Item` tuples or "fix" it; it is copied verbatim. Only trailing spaces and leading/trailing blank lines are trimmed.
- Since 2026-11 `MINHA` is only the **example** shown without an account: `RASC_EXEMPLO` = every card's `linhas` in file order, one blank line between cards (no `grupo` headings, no `titulo` — the owner asked for one big text with no sub-topics). It fills the read-only `#rasc-ta`; on a personal link the person's own text replaces it (see *Contas*). `titulo` / `grupo` / `conds` / `nota` are kept in the data but no longer shown.
- **Copiar tudo** copies the whole text; **＋ Receita** (`sendToRx`) appends only the selected passage (`rascSelection()`, the textarea selection) and switches on **edição livre**; nothing selected = warning toast.
- `"nota"` marks a card that was adapted from what the clinician pasted. The "Evolução diária — sala de emergência" card is the structure of a real evolution note with **all patient data removed** — never put identifiable patient data in this public file.

## Tests

Dev-only (the site never loads them). Requires Python 3, Playwright (`pip install playwright`; no browser download needed) and Chrome at `/usr/bin/google-chrome` (or `CHROME=/path`). No npm.

```sh
python3 tests/run.py                  # everything, compared against main (about 2 minutes)
python3 tests/run.py --ref <git-ref>  # compare against another ref (e.g. origin/main, HEAD~1)
python3 tests/run.py --quick          # parity on 3 conditions instead of 64
python3 tests/run.py --shots DIR      # also save screenshots (1440, 1366, 1280, 1024, 390, 320 px) into DIR
python3 tests/run.py --fv DIR         # also compare Escores with a local copy of fichavermelha.pages.dev (~3 min more)
python3 tests/run.py --fv DIR --write-fixtures   # ... and refreeze tests/fixtures/escores.json from the original
```

- `parity.py` exports the ref with `git archive` and drives **old and new pages in headless Chrome, over `file://` and over `http.server`**, only through the DOM: (on pages that have a Prescrições tab it clicks it first, since Meu rascunho is the home screen) (1) `DATA`/`KW`/`MINHA` source text (sha256 of the region from `const DATA = [` to the end of `KW`, and of `MINHA`) and parsed values must be identical; (2) for every condition × Adulto/Pediátrico × Ambulatorial/Internação × weight {none, 8, 20, 40, 70 kg} it clicks every **Adicionar receita**, every "escolha 1" option, every item, **Adicionar todas** and every orientation line, then changes the weight (15, 2,5, empty) and removes a chip, comparing the receita textarea and the chips after each step, plus the middle-column HTML; (3) Meu rascunho (new page only, since it changed on purpose): the example equals MINHA's lines, it is read-only, **Copiar tudo** copies it, **＋ Receita** appends exactly each selected passage; (4) the left-column filter for ~970 queries: every query that matched before must still match. Any console error/warning, page error, failed or external request fails the run. When the data is meant to change, parity against `main` will (correctly) fail on the data check — review the diff instead.
- `features.py`: routing (no hash = the offer page; `#/inicio` = the five tiles, a tile opens its tab and back returns to the tiles; the condition list is ready on the first click; each address form, 9 invalid hashes + an unknown condition, clicks + back/forward, typed address, state kept across tab switches) and search (ARIA wiring, `/`, Ctrl/Cmd+K, accent-insensitive results checked against an independent count, keyboard navigation, Enter/click opening a condition, opening a rascunho card, empty state, phone layout).
- `shots.py` (with `--shots`): screenshots of Prescrições with a condition open, Meu rascunho, the search with results, Escores (list, HEART, a rule, NIHSS, NEWS2, search with score results) and the 7-tab proof (dummy tabs registered at runtime, skipping those that already exist, up to 7); also asserts the tab bar stays one row with no clipped labels and no page-level horizontal scroll.
- `escores_golden.py` (always, `file://` and `http://`): replays the 1,982 cases frozen in `tests/fixtures/escores.json` (25 scores + NIHSS: nothing / everything / each item and option alone / numeric edges / band limits / seeded random; NIHSS also every quick-entry case) on the Escores tab (the NIHSS driver first unmarks the default zeros with real clicks, so every frozen case still starts from "nothing marked" as in the original) and compares value, band label and colour, conduta text, extra line, highlighted band, hidden items, pressed buttons, preview in Lista, Uma linha, MAIÚSCULAS and minúsculas, and the copied text (NIHSS: 4 moments × 3 formats + upper case, answered count, quick-entry value and warning).
- `escores_parity.py` (with `--fv DIR`, a local copy of fichavermelha.pages.dev with every `/<slug>/index.html`): byte equality of `data/escores.js`, the engine and NIHSS blocks and the images; parsed `ESCORES`/`GUIAS` deep-equal keeping `Infinity`; then the same driver on the original pages and on the tab for ~6,000 combinations (the fixture cases plus "every option over a full answer", more band-limit cases and 120 random per score). `--write-fixtures` refreezes the fixtures from the original (only when everything matched).
- `features.py` also covers Escores: tab order, list grouping, receita hidden on Escores and back with its content on Prescrições, addresses (`#/escores/<slug>`, invalid slug, back), the keyboard flow (search → Enter → arrows/Enter through HEART → Copiar), NIHSS quick entry, the NIHSS default (`nihss_padrao`: opens at 0 by address / list / search and copies with no click, equal to the frozen `tudo-0` case in every moment × format; quick entry replace / overwrite one digit / empty; Zerar tudo; unmark; tab switch vs fresh load; blank form still blank; the other 25 scores open blank; phone bar copies at once), score search ("nihss", "wells", "avc", "tep", "cha2ds2", "pneumonia"), the blank forms (print stubbed) and the 320px tab bar / result bar.
- `escores_layout.py` (always): for all 26 scores at 1366×768, 1280×720, 1024×768 and 1440×900, right after opening and after answering every item with real clicks: value, band and Copiar fully inside the visible area, `elementFromPoint` at the button's centre is the button, the sticky panel no taller than the visible area and covering no answer button.
- `integracao.py` (always, `file://` and `http://`): the five tabs together — receita hidden on Escores and Procedimentos and back with its content on Prescrições, Calculadoras and Meu rascunho; a weight typed in Prescrições or Calculadoras survives visits to Escores and Procedimentos and reaches the other tab; **Limpar** clears receita and weight everywhere; busca única groups in tab order, landing on a score, on a highlighted drug row inside a calculator and on a procedure by abbreviation (IOT, dreno, CVC); every **Doses:** link of every procedure opens the right Calculadoras page, and Back returns to the procedure with its checklist ticks, note values and open Doses box intact; the RSI standard pair is the same in both tabs (`CM.KIT_PADRAO` → Procedimentos defaults and the Calculadoras kit chips selected after the IOT Doses link) and changing it changes the Procedimentos default; 5-tab bar at 1366/1024/390/320 px (the home screen shows Meu rascunho active as the first tab at the left edge; one row, no clipping, active tab in view, no page-level horizontal scroll). With `--shots`, `shots.abas()` saves the header at each width, one screenshot per tab with something open and two multi-group searches.
- `parity.py` treats `KW` as append-only (phase 2 appended name synonyms to 34 entries): every old value must be a prefix of the new one; `DATA` and `MINHA` must stay byte-identical.
